# ACT Complete Business Wiki

## What This Actually Is

A **complete operating system** for running ACT Farm and the regenerative innovation studio. This captures:

- **How we make money** (not vague "business model" - actual processes)
- **The boring stuff** (receipts, invoices, accounting - made less painful)
- **All the projects** (JusticeHub, Empathy Ledger, The Harvest, BCV, Goods, Art)
- **Who does what** (real roles, not org chart fantasies)
- **How things connect** (GHL → Notion → Supabase → everywhere)
- **When to think about things** (notifications for what matters)

This is **everything a business needs to run**, documented honestly.

## How Money Works (Real Talk)

### Revenue Sources

**[[business/revenue-streams]]**
- **JusticeHub**: $15K-25K/month (NDIS, contracts)
- **The Harvest**: $5K-12K/month (memberships, CSA, workshops)
- **BCV Residencies**: $2K-8K/month (low volume, high value)
- **Goods on Country**: TBD (launching)
- **Grants**: $20K-80K/year (sporadic, project-specific)
- **Art Commissions**: $5K-15K/quarter (irregular)

**Total**: ~$30K-50K/month average (high variability)

### Cost Structure

**[[finance/cost-structure]]**
- **People**: $15K-25K/month (Ben, part-time team)
- **Land/Facilities**: $3K-5K/month (mortgage, maintenance)
- **Operations**: $2K-4K/month (software, supplies, travel)
- **Tech**: $500-1K/month (hosting, tools, subscriptions)

**Burn Rate**: ~$20K-35K/month
**Runway**: Track in [[finance/cashflow-forecast]]

### Pricing Strategy

**[[business/pricing-philosophy]]**
- **Premium**: Align price with regenerative value
- **Transparent**: No hidden costs, published pricing
- **Prepaid**: Cashflow stability (residencies, CSA, memberships)
- **Sliding Scale**: Where mission requires (JusticeHub youth)
- **Beautiful Obsolescence**: Price to sustain until community owns

## Generative Notifications (When to Think About What)

### The Problem
Too many things to remember. Invoices due, receipts to file, grants to apply for, projects to review, people to follow up with.

### The Solution
**[[notifications/smart-reminders]]** - System that knows when to prompt you

**Examples**:
- **Finance**: "15 receipts collected this month, time to reconcile?" (monthly)
- **Projects**: "JusticeHub hasn't had a health check in 6 weeks" (every 4-6 weeks)
- **Funding**: "Harvest Grant closes in 2 weeks, draft ready?" (grant deadlines)
- **Operations**: "3 GHL automations failed this week, review needed" (weekly)
- **People**: "Haven't checked in with X in 3 months" (relationship maintenance)

**How it works**:
1. Living Wiki tracks what you've documented
2. Scans Gmail/Calendar/Notion for patterns
3. Learns your rhythms (when you usually do things)
4. Prompts generatively: "Based on last 3 months, you usually [X] around now"
5. Makes boring stuff less painful by reminding you at right time

**See**: [[notifications/design]] for full implementation

## Making Boring Stuff Fun (Gamification)

### Receipt Workflow Leveling System

**[[finance/receipt-game]]**

Instead of "ugh, receipts", make it:
- **Streak**: 7 days in a row = "Receipt Ninja 🥷" badge
- **Speed**: Process 10 receipts in under 5 minutes = "Flash Accountant ⚡"
- **Accuracy**: 95%+ auto-extraction match = "OCR Master 🤖"
- **Monthly**: Close books in under 2 hours = "Finance Speedrun 🏃"

### Funding Application Tracker

**[[finance/funding-game]]**

Turn tedious grant writing into:
- **Pipeline View**: Visual progress (like Kanban, but for money)
- **Win Rate**: Track conversion (applied vs awarded)
- **ROI**: Hours spent vs $ raised = efficiency score
- **Templates**: Reuse answers, level up speed
- **Team**: See who writes best sections (collaborative improvement)

### Invoice Collection Game

**[[finance/invoice-game]]**

Make "getting paid" satisfying:
- **Sent**: Green = sent, Yellow = due soon, Red = overdue
- **Automation**: Auto-follow-up at 7, 14, 30 days = less nagging
- **Streak**: Get paid within terms X months in a row = "Cashflow Champion 💰"
- **Average Days**: Track average time to payment (gamify improvement)

## Using the Small Language Model

### What the SLM Does

**[[integrations/slm-assistant]]**

1. **Rollup Reports**: Scans all projects, summarizes health
2. **Pattern Detection**: "Harvest bookings always spike after Instagram posts"
3. **Anomaly Alerts**: "BCV inquiries dropped 40% this month, investigate?"
4. **Smart Summaries**: Condense 50 Notion pages → 5 key insights
5. **Draft Assistance**: "Here's a grant application draft based on past wins"
6. **Knowledge Extraction**: Auto-adds to Living Wiki from Gmail/Calendar

### How to Use It

**Daily**:
```
"What needs attention today?"
→ SLM scans GHL, Notion, Wiki, Calendar
→ Returns: 3 urgent, 5 important, 12 can wait
```

**Weekly**:
```
"Project health summary"
→ SLM reads all project Notion pages, GHL pipelines
→ Returns: Traffic lights (🟢🟡🔴) for each project
```

**Monthly**:
```
"Finance close assistant"
→ SLM finds unreconciled receipts, missing invoices
→ Generates checklist for month-end
```

**Quarterly**:
```
"Strategic review prep"
→ SLM summarizes 3 months of activity across all projects
→ Identifies patterns, wins, problems
```

## First Principles Thinking

### Stop Doing Stupid Tech Shit

**[[processes/tech-philosophy]]**

❌ **Don't**:
- Add new tools because they're shiny
- Build custom when off-the-shelf works
- Overcomplicate simple workflows
- Automate before understanding manual process
- Create integrations that need constant maintenance

✅ **Do**:
- Use what's already working (GHL, Notion, Supabase, Vercel)
- Document processes BEFORE automating
- Choose boring technology (Next.js, PostgreSQL, not bleeding edge)
- Delete features/tools more than you add
- Ask: "Will this still work in 2 years with zero maintenance?"

### Technology Principles

1. **Fewer tools, used fully** > Many tools, used partially
2. **Boring technology** > Shiny new tech
3. **Document first, automate second** > Automate without understanding
4. **Delete features** > Add features
5. **Works in 2 years** > Perfect today, broken tomorrow

## Philosophy

This wiki captures **how ACT actually runs**, not how we wish it ran or how business books say it should run.

**We document**:
- Real revenue and costs (not projections)
- Actual workflows (not ideal processes)
- Boring stuff (receipts, invoices, accounting)
- What's broken (not just what works)
- How things connect (integrations, dependencies)

**We don't document**:
- Corporate mission statements (we have real work to do)
- Theoretical best practices (we document actual practice)
- Stuff that changes daily (that belongs in project management)
- Perfect processes (we document what actually happens)

**The wiki serves the business, not the other way around.**
