## The one thing to read if you read nothing else

The site had **twenty admin pages, sixteen prototype pages and twelve mutating API
routes reachable by anyone on the internet**, including a 50 MB upload straight
into Supabase Storage and an LLM endpoint that spends money per call. `robots.txt`
disallowed them, which is a request to crawlers, not access control.

That is closed. `src/middleware.ts` answers 404 for unauthorised page requests and
`requireInternal()` answers 401 for the APIs, both keyed on `ACT_INTERNAL_TOKEN`,
which is set in Vercel Production. Missing token means open in development and
**closed** in production: a deploy that forgets the variable locks operators out
rather than letting the public in. Verified against a real production build with
no token set.

## What shipped

### Token layer
- `tailwind.config.ts` was `theme.extend = {}`, so brand colours were unreachable as
  utilities and the codebase had drifted to 341 hex literals plus a third palette.
  Tokens were **measured off the rendered homepage**, not transcribed from a spec.

  rule that has already caught one the bulk replacement missed.
- Named `forest`, **not** `green`: overriding `green` would shadow Tailwind's default

### Accessibility
- 19 WCAG AA violations across the live routes, now **zero**.
- Root cause: **no accent works on both light and dark.** Every field's accent failed
  on one side, goods failed on both. Fields now carry `accentOnLight` / `accentOnDark`;
  the plain accent is decoration only.
- `npm run check:contrast` runs blocking. It skips ~657 elements per run (text over
  photographs, translucent backgrounds) because contrast there cannot be decided from
  computed style. **"Zero violations" means zero decidable violations.**

### Links and IA
- The nav and footer pointed at `/projects`, `/blog`, `/farm`, `/method` and seven
  others, all 307s. "Connected projects" chips on 17 of 29 article pages pointed at
  `/projects/<slug>`, a 308.
- The site collapse itself was **sitting uncommitted**: 23 redirects that were never
  live, so production served the old IA alongside the new one. Now shipped.
- Every link on every live public page resolves to 200, verified by
  `scripts/sweep-routes.mjs`.

### Field graph — the part the editorial work builds on
- `src/lib/fields/field-graph.ts` joins three datasets that each named things
  differently and never read across each other.
- **Guard:** every project slug and question tag must be mapped, including ones that
  deliberately belong to no field (mapped to `null`, not omitted). A slug that is
  merely absent would drop out silently and a field page would look complete while
  showing less. `unmappedReferences()` is asserted empty.
- Art had zero articles because **Empathy Ledger's taxonomy has no art project**.
  `src/data/field-assignments.ts` is the curated overlay, and it survives the sync
  that rewrites the generated JSON on every build.
- Article pages previously suggested "the three most recent articles", so all 29
  recommended the same three. They now rank by shared field.

## Traps worth knowing

- **The tests need a running server.** They have a preflight that says so plainly.
  Port 3001 is busy on this machine; a run against another session's server produced
  sixteen failures that all read as "the middleware is broken". Use `TEST_BASE_URL`.
- **`publishedAt` in the editorial feed is a migration artifact.** 21 of 29 articles
  share one timestamp to the millisecond; `createdAt` and `updatedAt` each hold a
  single value across the whole corpus. No dates are rendered because of it. There is
  an inverted test that **fails the day the feed gains real dates** and names the file
  to change.
- **`npm run build` runs eight sync scripts** that hit Empathy Ledger and Notion and
  rewrite generated JSON. Use `npx next build` when you only want to check compilation.
- **The shell here is zsh**, which does not word-split unquoted variables. A loop over
  `$BRANCHES` silently treated fourteen names as one.

## Next: editorial work against the Empathy Ledger API

The field graph is the spine; the content is what is thin. Three things, in the order
I would do them.

### 1. The taxonomy gap is upstream, not here
Empathy Ledger's project slugs are `justicehub`, `goods-on-country`, `empathy-ledger`,
`the-harvest`, `black-cockatoo-valley`, `act-farm`. **There is no art project**, so the
Art field can only ever be populated by the local overlay in `field-assignments.ts`.

That is arguably correct — art is a lens, not a delivery vehicle, and `living-field.ts`
already says CONTAINED "belongs to the Art field and grows through JusticeHub". But it
means the API contract and the site's IA disagree about what a field is. Worth deciding
deliberately: either EL grows a concept that can express "this piece is art **and**
justice", or the overlay stays the permanent home for that judgement.

### 2. Eleven articles still attach to no field
Reviewed one by one this session; four moved (`naidoc-with-jimmy` → goods,
`vireak` → justice, `the-spirit-must-be-strong` → goods,
`seeds-of-change` → justice). Seven stayed, each with a reason recorded in
`DELIBERATELY_UNASSIGNED`. They are personal essays, a Vietnam piece outside the five
fields, and Conversation Camp, which happened at Black Cockatoo Valley and would be in
the wrong place under Harvest.

Current coverage: justice 11, goods 7, empathy 4, harvest 3, **art 3**, unattached 7.

### 3. Art opens the homepage and has three articles
"Art moves first" is the first line a visitor reads, and the Art field is `01`. Three
pieces is thin for the claim. This is a commissioning question, not a code one.

### Also worth a look
- `primaryProject` is empty on all 29 articles; only `relatedProjectSlugs` carries the
  edge. If EL can populate `primaryProject`, the graph gets a cleaner signal than the
  union it currently computes.
- `themes` is empty on all 29 despite existing in the schema.
- Real `publishedAt` values would let the field pages sort meaningfully and show dates.
